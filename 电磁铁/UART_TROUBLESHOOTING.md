# 串口通信故障排查

## 1. 上位机提示没有找到串口

依次检查：

1. USB-TTL 是否插入电脑。
2. Windows 设备管理器中是否出现 `COMx`。
3. 是否安装 CH340、CP210x 或 FTDI 驱动。
4. 是否点击了上位机的“刷新串口”。
5. USB-TTL 是否损坏。

## 2. COM 口能看到，但打开失败

常见原因：

- 串口助手已经占用了该 COM 口。
- 另一个上位机窗口已经连接。
- 设备管理器中的 COM 号发生变化。
- USB-TTL 驱动异常。

关闭其他串口软件后重新连接。

## 3. 能打开 COM 口，但收不到回复

按下面顺序检查：

1. USB-TTL TXD 是否接 PA10。
2. USB-TTL RXD 是否接 PA9。
3. GND 是否共地。
4. 单片机是否已经烧录串口版程序。
5. CubeMX 是否配置 USART1。
6. `USART1 global interrupt` 是否开启。
7. 上位机是否为 `115200 8-N-1`。
8. `main_uart.c` 是否真正替换了工程里的 `main.c`。
9. STM32 是否复位或重新上电。

正确接线不是 TX 接 TX，而是：

```text
USB-TTL TXD -> STM32 PA10
USB-TTL RXD -> STM32 PA9
```

## 4. 收到乱码

优先检查：

- 波特率是否都是 115200。
- 数据位是否是 8。
- 校验位是否是 None。
- 停止位是否是 1。
- 系统时钟是否与 `SystemClock_Config()` 匹配。
- USB-TTL 是否是 TTL 电平，而不是 RS-232。

## 5. 收到 `ERR COMMAND`

命令必须严格是：

```text
SET 0
SET 1
SET 2
SET 3
GET
NEXT
```

不要发送：

```text
SET=2
state 2
设置2
```

电脑程序会自动添加 `\r\n`，不要手动重复添加。

## 6. 收到正确回复，但电磁铁不动作

此时串口已经正常，检查控制输出和功率部分：

1. 用万用表检查 PB0、PB1、PB10。
2. 检查 MOSFET 模块输入端是否接对。
3. 检查 STM32 GND 和 MOSFET GND 是否共地。
4. 检查电磁铁外部电源。
5. 检查电磁铁额定电压。
6. 检查驱动模块的触发逻辑。
7. 检查电磁铁输出端接线。

当前程序定义为：

```c
#define APP_MAGNET_WORK_LEVEL GPIO_PIN_SET
#define APP_MAGNET_STOP_LEVEL GPIO_PIN_RESET
```

这表示高电平吸合。如果你的模块是低电平触发，需要交换这两个定义。

## 7. 按实体按钮时程序卡住

本目录的 `main_uart.c` 使用非阻塞按键消抖，正常情况下不会因为按住按钮而停止串口处理。

如果仍然卡住：

- 确认烧录的确实是 `main_uart.c`。
- 确认没有误烧录原来的按钮版 `main.c`。
- 检查 PA0 是否悬空。

## 8. 电磁铁动作时 STM32 重启

优先处理电源和干扰：

- 电磁铁必须使用独立电源。
- 电磁铁额定电流不能超过驱动模块能力。
- STM32、驱动模块、外部电源负极必须共地。
- 每个线圈需要续流二极管，或确认驱动模块自带。
- 电磁铁功率线和串口信号线分开布线。
- STM32 电源附近增加合适的去耦电容。
- 检查外部电源是否因吸合瞬间掉压。

## 9. 重新连接后上位机状态显示未知

连接时上位机会自动发送：

```text
GET
```

如果没有更新，查看通信记录：

- 有 `>> GET`、没有 `<< OK STATE=...`：检查串口接收方向和单片机程序。
- 两边都有记录、但状态格式不对：检查返回内容是否被其他程序修改。
